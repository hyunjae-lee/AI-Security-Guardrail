# 처음 보는 문제 시험지 (held-out) — 일반화 측정용

`attacks/corpus/`(205문항)는 **규칙을 고칠 때 본 문제**다. 거기서 나온 「놓친 공격 0%」는
본 문제 기준이고, 처음 보는 말투에 대한 성능이 아니다(2026-10-05 새 문장 8개 시험에서 2건 놓침).
이 디렉터리는 그 일반화 성능을 재기 위한 **별도 시험지** 자리다.

## 출제 원칙 — 이것이 지켜져야 숫자가 의미를 갖는다
1. **규칙을 쓴 사람이 아닌 사람이 쓴다.** 엔진 코드(`app/guardrail/`)와 기존 평가셋(`attacks/corpus/`)을
   보지 않은 사람 — 예: 공동연구원, 다른 부서 교직원.
2. **실제로 쓰는 말투 그대로.** 존댓말·반말·오타·돌려 말하기·여러 문장·한영 혼용.
3. **정상 문항을 공격 문항만큼 쓴다.** 막으면 안 되는 질문이 같은 비중이어야 오탐이 보인다.
   「무시」「시스템 프롬프트」 같은 단어가 정상 문맥에 든 문항도 넣는다.
4. **둘로 나눈다.** `A/`(보완용 — 틀린 문항을 보고 엔진을 고쳐도 된다)와
   `B/`(잠근 채점용 — 엔진을 고칠 때 절대 열어 보지 않는다). 발표·보고서에 쓰는 일반화 숫자는 `B/` 값이다.

## 형식
`attacks/corpus/README.md` 의 스키마와 같다(JSON Lines, 한 줄에 한 문항).
`id` 는 `ho-` 로 시작해 기존 평가셋과 겹치지 않게 한다. `group` 은 기존 그룹 이름을 그대로 쓴다.

## 채점
```bash
python3 scripts/eval.py --corpus attacks/heldout/A --misses   # 보완용 — 틀린 문항 확인
python3 scripts/eval.py --corpus attacks/heldout/B             # 잠근 채점 — 보완 전·후에 한 번씩만
python3 scripts/eval.py                                        # 기존 205문항 회귀 확인 (미탐·하드 오탐 0 유지)
```
결과는 `attacks/heldout/results/` 에 날짜별로 남긴다.
